# 《用 Codex 做个人网站并部署到 Cloudflare》讲稿备注

总时长：约 10 分钟。正常讲到 9 分钟，留 1 分钟处理页面加载、现场停顿或提问。

## 第 1 页｜开场（0:00–0:40）

今天分享一个我自己刚做完的项目：用 Codex 做个人网站，然后部署到 Cloudflare。

我主要讲四件事：为什么值得做、大家怎么照着复刻、为什么我建议把域名放在 Cloudflare，以及最后怎样发布并看到真实访问数据。

今天不展开讲代码。大家只要记住整个流程，回去准备好资料就能开始。

过渡：先说最基础的问题——已经有微信、公众号和小红书了，为什么还要个人网站？

## 第 2 页｜为何要做个人网站（0:40–1:45）

我以前介绍自己，要分别发送个人简介、项目截图、服务链接和联系方式。对方收到一堆零散信息，也不一定愿意全部打开。

个人网站解决的是信息入口问题。以后别人问我在做什么，我只需要发一个网址。

它还有两个很实际的好处：以前做过的项目不会被朋友圈和信息流冲走；页面怎么展示、先看什么、最后点哪里，都由我决定。

一句话总结：发一个网址，比发一串截图和链接省事。

## 第 3 页｜展示真实结果（1:45–2:35）

这是我做出来的网站。我没有一开始就做很多栏目，只做了一页。

这一页放了个人定位、正在做的项目、服务入口和联系方式。手机和电脑都能打开。

现场动作：打开真实网站，快速滚动一遍。重点展示首页标题、TZ Mall、联系方式和二维码。控制在 30 秒以内。

过渡：看到结果以后，下面直接说怎么复刻。

## 第 4 页｜四步快速复刻（2:35–3:45）

第一步，准备资料：一句个人介绍、三个真实项目或服务、一个联系方式。

第二步，把这些资料交给 Codex，同时说明给谁看、页面要放什么、希望是什么风格。

第三步，检查第一版。先检查内容是否真实，再检查链接、二维码和手机布局。

第四步，具体修改。不要只说“再好看一点”，直接指出哪个位置、哪些内容保留、改成什么样算完成。

这四步里，最重要的是资料真实。资料越具体，第一版越接近你。

## 第 5 页｜可直接复用的提示词（3:45–4:55）

这一页可以让大家直接拍照。

提示词只需要说清四件事：我是谁、服务谁、页面放什么、希望访客做什么。

第一次生成时，我建议加一句“先给我看第一版，不要发布”。这样可以先检查虚构内容、错误链接和手机显示，再决定是否上线。

现场可补充：如果有喜欢的网站，可以把网址或截图一起交给 Codex，作为风格参考。

## 第 6 页｜为何在 Cloudflare 买域名（4:55–6:15）

域名可以理解成网站在互联网上的固定门牌号。平台提供的临时网址可以先用，但自己的域名更容易记，也方便长期使用。

我建议在 Cloudflare 买域名，主要有三个原因。

第一，注册和续费按成本价，不额外加价。第二，在注册局允许的情况下，公开查询时会隐藏大部分个人资料。第三，域名、DNS、Workers 和 HTTPS 都在同一个后台，部署时少切换几个系统。

域名也可以在其他平台购买，再接入 Cloudflare。这里推荐 Cloudflare，主要考虑后续部署方便。

口播提醒：不要说“域名免费”或“网站永久免费”。域名需要付费；Cloudflare 的免费服务也有用量限制。

## 第 7 页｜Codex 一键部署（6:15–7:45）

这里说的“一键”，有一个前提：Cloudflare 账号已经登录，域名已经准备好。

网站检查完成后，我只需要发一条发布指令。Codex 会运行正式构建、部署到 Cloudflare Workers、绑定域名，并把可以访问的 HTTPS 网址交给我。

我不需要单独买服务器，也不用自己安装 Nginx 或手工申请 SSL 证书。绑定自定义域名后，Cloudflare 会创建相应的 DNS 记录并签发证书。

现场演示建议：提前把网站和账号准备好。现场只展示发布指令、确认操作和最终 HTTPS 网址。若网络不稳定，直接播放录屏。

## 第 8 页｜Cloudflare Web Analytics（7:45–9:00）

网站上线以后，我还想知道三件事：有没有人来、他们从哪里来、页面打开和交互是否顺畅。

Cloudflare Web Analytics 的接入很简单。进入 Cloudflare 后台的 Web Analytics，添加网站并选择域名。走 Cloudflare 代理的域名默认可以自动接入；如果是手动接入，就把后台给出的 beacon 脚本放到页面结束的 `</body>` 标签之前。Cloudflare Pages 项目还可以直接在 Metrics 里开启，下一次部署时自动加入脚本。

它能看到页面访问量、访客、来源、国家、浏览器和设备，也能看到 LCP、INP、CLS 三项 Core Web Vitals。对个人网站来说，这些数据足够判断哪一页有人看、流量从哪里来、页面体验是否需要优化。

优点有三个。第一，免费；第二，隐私优先，Cloudflare 官方说明它不收集或使用访客的个人数据，性能指标也不依靠 Cookie、localStorage 或指纹识别；第三，域名、部署、HTTPS 和统计都在同一个后台，维护成本很低。

局限也要讲清楚。第一，广告拦截器、Brave 或隐私扩展可能拦截 beacon，因此后台数字可能低于真实访问量。第二，它暂不支持 UTM 参数和自定义事件，不适合分析按钮转化、广告归因或完整用户路径。第三，最近 7 天保留未抽样的 beacon 数据，更早的数据会聚合；后台查询也可能根据数据量动态抽样。

所以我的用法很明确：用它看个人网站的访问趋势和真实页面性能；需要复杂转化漏斗时，再补一套更专业的分析工具。

过渡：网站做出来、发出去、还能看到使用情况，整个闭环就完成了。

## 第 9 页｜收束（9:00–10:00）

如果大家今晚想开始，只需要准备三样东西：一句个人介绍、三个真实项目或服务、一个联系方式。

先让 Codex 做出一页网站，确认内容和风格，再购买或绑定自己的域名，最后发布并打开 Analytics 看真实数据。

个人网站不用第一次就做完整。先把真实信息整理出来，拿到一个能访问的网址，之后有新项目再继续更新。

结束句：如果你愿意把这三样资料准备好，做个人网站这件事就已经开始了。
